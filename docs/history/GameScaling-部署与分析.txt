如何使用
1. 双击 ${DEPLOY_ROOT}\START.bat，保持启动窗口运行。若接口已在运行，不要重复启动。
2. 双击 TEST.bat，使用官方 Doom 样例截图测试模型返回动作，结果在 reports\streaming-test.json。
3. 使用 PCL 正常启动你的 TEST_INSTANCE，进入单人世界。
4. 双击 MINECRAFT.bat：默认只观察、打印动作，不发送键鼠。
5. 把 Minecraft 放到前台，按 F8 开始/暂停；F9 结束。
6. 要执行动作，在命令提示符运行：
   ${DEPLOY_ROOT}\MINECRAFT.bat --execute --title "Minecraft" --goal "Explore nearby terrain and stay alive."
   如果窗口标题没有 Minecraft，把 --title 改为实际标题中的一段文字。
7. STOP.bat 停止本部署保存并核验过进程身份的后端和适配层；也可在 START 窗口 Ctrl+C。

NInfer + KVMem + streaming 的核对结果
实际核对并复制了你本地的：
${ENGINE_BASELINE}\Bonsai-Swift-Portable\engines\sm89-fusion-20261020\ninfer-serve-89.exe
对应源码：${ENGINE_BASELINE}\build-tools\engine-updates\fusion-20261020\source\src-tree\fusion-engine-src
使用其转换工具，生成 models\ninfer\gamescaling-0.8b-s3-q8.ninfer（1,521,412,096 字节）。文本 Q8，视觉 BF16，无 MTP。
本目录 converter 是独立副本。修复转换工具缺少 artifact identity 的问题，以及沙箱环境不允许硬链接时的 Windows 文件发布方式；原有源码没有修改。
真实加载错误：text/layers/0: input projection: unsupported logical projection geometry
根因在 src\ops\weight_input.cpp 的 input_projection：检查固定 27B Dense / 35B MoE 投影尺寸。
0.8B 的 hidden_size=1024，无法通过；配置解析和文件转换成功并不等于计算内核支持。
2B/9B 也不能仅因 Qwen3.5 架构同名就保证支持。要支持小模型，需要适配融合投影、GDN、视觉尺寸及相应执行路径，并做数值验证。
27B 的文本尺寸更接近现有路径，但官方 BF16 权重约 54.7GB；普通 4bit 仅原始权重理论下限也约 13.5GB，超过本机 8GB。
不能把 Bonsai 的特殊三值压缩效果自动迁移到 GameScaling，也不能把现有 Swift 权重重命名当作 GameScaling。
现有转换制品和错误日志作为兼容性证据保留，见 logs\server.log。未启动的 NInfer 制品不要当作可用模型。
因此本次落实的是：llama.cpp + 多模态模板适配 + SSE streaming。它没有运行你那版 NInfer KVMem。

MTP：全部八个官方检查点的核验
0.8B S1/S3：474 个权重张量；2B S1/S3：618；9B S1/S3：760；27B S1/S3：1184。
通过 safetensors 头或分片索引逐一检查，均没有 MTP/draft/nextn 张量；本次没有使用任何外置预测头。
0.8B-S3 配置虽然写有 mtp_num_hidden_layers=1，实际权重并不包含该头。
结论：这些公开检查点不能直接使用原生 MTP 推测解码。六段动作是 action chunking，不是一次前向预测多个 token 的 MTP。
额外训练或移植匹配的 draft/MTP 头是后续实验；原始 Qwen 头与续训后的隐藏状态分布未必匹配，接受率和净速度必须测量。
推测解码一般由主模型验证候选；不应把未经验证的草稿动作提前送进游戏。

决策是怎么来的
官方训练/评测使用 Qwen3.5 视觉语言骨干，官方发布脚本实测 vLLM 0.17.0；论文评测通过 H200 集群的 vLLM API。
它不是依赖 vLLM 才具有游戏能力：权重、视觉处理、tokenizer、聊天模板和动作协议才是需要保持一致的部分。
输入为游戏规则/目标、当前截图、历史截图与动作。视觉编码器提供图像特征，语言骨干自回归产生可选推理及结构化动作。
训练采用 assistant 回复上的 next-token prediction，学习人类轨迹中的操作；部分轨迹附有稀疏推理说明。并非实时搜索整棵游戏状态树。
一次动作规划覆盖约 200ms：6 组键/鼠标按钮，每组约 33ms，另有该动作块的鼠标横纵位移和滚轮。
官方客户端默认保留 5 个历史回合。本地游戏入口为减轻延迟使用 2 个历史回合、854x480 图像、关闭显式思考、最多 256 输出 token。
训练/协议的 5Hz 观察和 30Hz 子动作，不是这台机器已经达到的推理速度保证。

“更深层数据”能力
模型默认只看到你送进去的图像和文字。没有自动读取 Minecraft 进程内存、方块地图、实体列表、玩家 XYZ 或服务器状态的能力。
网络隐藏状态、GDN recurrent state、KV cache 都是模型的内部表示，不是游戏引擎的真实状态。
可以用客户端 Mod、游戏开发接口或受控测试环境导出 position、velocity、yaw/pitch、health、inventory、block/entity 等信息，再由适配器提供给模型。
仅追加文本可做零样本实验，但它主要按截图+键鼠轨迹训练；长期可靠使用结构化状态仍需匹配数据微调与评测。
如果能拿到真实碰撞、导航网格和目标坐标，低层控制器通常应直接使用这些数据，无需让模型重复猜测。

XYZ / 矩阵 / aim 方案
可以设计这种控制接口，但分两条路线：
A. 不重训：仍由 GameScaling 输出训练过的键鼠符号；在执行器把它们映射成局部移动向量、世界速度和视角增量。模型内部动作语义未变。
B. 改动作空间：让策略输出 waypoint_xyz、velocity_local、look_direction 或 target_xyz；用相应轨迹标签微调/训练，再接低层控制器。
仅改提示词，把 W 改名为 X 或把鼠标 X/Y 改成世界 XYZ，不会自动获得这种能力；动作解析器、历史记录、训练目标均需一致更改。

具体数学：
给出玩家位置 p 和相机旋转 R，可构造 4x4 相机/角色到世界的齐次变换 T=[R p; 0 1]。
键盘方向可先写成局部二维输入 (D-A, W-S)，归一化后乘移动速度，通过角色 yaw 的旋转映射到世界平面。
站立、走路、冲刺、空中、游泳、载具、碰撞及对角速度都需要执行器按游戏物理处理。移动到世界坐标不等于传送到该坐标。

aim 推荐为单位视线方向 d，或者目标点 q。若已知眼睛位置 p_eye，则 d=(q-p_eye)/||q-p_eye||。
屏幕中心对应一条射线，而非唯一三维目标点：q=p_eye+lambda*d。没有深度或目标位置时，lambda 不可由单个中心像素唯一确定。
已知相机内参 K 和姿态 R 时，任意像素的世界射线方向为 normalize(R*K^-1*[u,v,1])。
“视线中心的法向量”可理解为相机前向单位向量；更准确的接口名是 look_direction，而非目标表面的法向量。
仅方向有两个自由度，不能表达位置、目标距离或相机 roll；完整姿态可用四元数或旋转矩阵。

Minecraft 约定：+Y 向上；yaw=0 指向 +Z，yaw=+90 指向 -X；pitch 向下为正。
d=(-sin(yaw)*cos(pitch), -sin(pitch), cos(yaw)*cos(pitch))。
目标角度 yaw=atan2(-dx,dz)，pitch=atan2(-dy,sqrt(dx^2+dz^2))。
角度差要 wrap 到 [-180,180)，再用经过灵敏度标定的控制器生成相对鼠标输入，或使用 Mod 接口更新视角。
不能直接拿鼠标屏幕千分比等同于 yaw/pitch；raw mouse、灵敏度和镜头模式会改变关系。
tools\world_coordinates.py 提供这些转换，并通过基本方向检查；它不负责获取实时世界状态、碰撞或寻路。

是否会更快
MTP 优化 token 解码；KVMem 主要优化模型上下文存储/检索；SSE streaming 让 token 更早送达。它们不是同一件事。
完整决策延迟包含截图/编码、视觉编码、历史 prefill、动作解码、传输、动作执行。35 个输出 token 很短，视觉和 prefill 常常不可忽略。
streaming 不等于完整动作已可执行。本地脚本等待动作块完整并解析成功后才执行，避免半个动作改变游戏。
滚动历史会删除最早图像，破坏长前缀的相同部分，不能把同图重复请求的缓存速度当成持续游戏速度。
200ms 动作块对应理想 5 次决策/秒，本机当前静态测试约 0.42–0.71s，尚不满足稳定 5Hz；更适合可暂停/低节奏实验。
如果未来移植 NInfer 小尺寸路径，应使用相同图像、历史长度、精度和采样比较端到端延迟、动作合法率、游戏成绩，而不只比较纯文本 tok/s。
